## Standing rules
- **Editing and input are consistent between the window version and the console version** (owner's rule, 2026-10-31): line input of the prompt / `INPUT`, the one-line editor, the full-screen editor, the monitor, break keys (ESC and Ctrl-C), key codes and escape sequences. A change to one host is a change to the other (or a written reason why they differ); prefer shared code behind a small driver interface to two copies.
- **Never break the program file format** (owner's rule, 2026-11-03): a saved `.e99` must always load; changes bump the header version and keep the old versions readable (with a test per version). **`SAVE "name"` is the ASCII listing by default** (`.bas`), `SAVE "name",B` the binary form.
- **Uninitialized memory** (owner's rule, 2026-11-03): locals, `malloc()` and the new part of `realloc()` are uninitialized: set them before use (`memset` / `calloc` / initializer). Check new code for it; first suspect when a bug shows on some machines only (e.g. the screen flicker fixed by the `memset` in `txtscr_initscreen()`).
- **Never run git write commands** (commit, add, push, merge, rebase, reset, checkout of files, stash, tag, branch changes). The user does all of these manually, even if git access is authorized later. Read-only git (`status`, `log`, `diff`, `show`) is fine.
- Keep this file and `docs/` current when work changes the state.
- Keep the man pages current (`man/*.1`, `man/*.7`; `make man-check` must pass, `sh mancheck.sh --update` rewrites the list of reserved words): options, environment variables, statement/function groups, drivers, `BUILD` and exit status changes go into them in the same piece of work.
- Keep the grammar current: a new statement, function or operator gets its rule in `bascomp.ebnf`, then `make grammar` regenerates the quick reference `docs/grammar.md` / `docs/grammar.html` (`make grammar-check` verifies it).
- Keep `HistoryLog-Claude.md` current: new work goes under its "Pending" section; after the user commits, move it into the log with the commit ID and timestamp (see `CLAUDE.md`).

- **Clean up test processes** (owner's rule, 2026-11-05): every background program started for a test (Xvfb, metacity, engine binaries, runners) gets a `timeout`, its PID is recorded and it is killed in the step that ends the test; at the end of each piece of work check `ps -eo pid,etimes,args | grep -E 'Xvfb|metacity|engine1999|test1'`. Logs go to the scratchpad, never into the repo. (The owner had to kill many leftovers by hand.)
- **Milestone backups are my safety net; one roadmap item per unattended stretch** (owner's rules, 2026-11-04): when I divide a roadmap item into milestones, I run `./backup.sh --label <what>` at **each** milestone (a ZIP of the working tree in `backups/`, no git) and also before a risky step (label `pre-<what>`). If something goes awry I restore it myself: `./backup.sh --list`, `./backup.sh --restore <zip>` unpacks into `backups/restored/<name>/` and lists the differences, then I copy back the files I need (never wholesale over work I want to keep). The backups are a tool for me, not for the owner. **At a roadmap boundary I stop**: when the owner is away and has not said otherwise, at most ONE roadmap item per stretch (finish it, check it, bookkeeping in `SESSION.md`, `HistoryLog-Claude.md` Pending and the docs, a last backup), then wait; the owner looks at the result and commits it into git. The next item starts when the owner is back and says so (or when he named several items himself, as with "do them all").
- **No locks on the layer memory** (owner's design, restated 2026-11-01): the screen thread reads the layers and text screens without synchronization; the content may be torn, but nothing may be freed / reallocated, indices must stay bounded, and nothing may be *lost*: shared state is owned by one thread and handed over by atomic words (GCC `__atomic` builtins, no mutex, no pthreads). Rules: `docs/display-engine.md`, "Threading". Don't add mutexes around layer memory.

## What exists (the whole pipeline works)
- **CHR$(n)** is implemented (token `CHR` 146, instruction `CHRS` 0x126; n must be 0..255, else "Illegal argument"; strings are binary-safe since 2026-10-31).
- **INPUT and GET** are implemented (`INPUT [#ch,] ["prompt"(;|,)] vars`, `GET [#ch,] vars`; instructions `INPL 0x134, INPN 0x135, INPS 0x136, INPE 0x137, GETK 0x138`; host callbacks `vm->input` (line) and `vm->getkey`; see `docs/basic-language.md` and `docs/compiler-and-vm.md`).
- **DATA/READ/RESTORE** are implemented (parser, `cgendecl.c`, instructions `RDNM` 0x117, `RDST` 0x11E, `RSTR` 0x11F; see `docs/compiler-and-vm.md`).
- **Tokenizer** (`bastok`): heap strings, growable buffers, identifiers/literals ≤ 65535 bytes; line numbers 0..999999 (24 bit); `linehdr_t` = `{lineno.24, length.16}` (`LINEHDR_SIZE` = 5). Keywords `AGAIN` (token 145) and `CHR` (token 146) were added.
- **Program store** (`baspgm`/`baslin`): doubly linked list of heap `line_t` nodes; `save_program()` (ascii listing or binary encoded lines preceded by a 5-byte header: magic `89 45 39 39` + version 1, see `PGMFILE_*` in `baspgm.h`; `read_program_header()` identifies it; the loader is `repl_load_program()` in `basrepl.c`, see the LOAD entry below).
- **Code/data segments** (`codegen_t`): heap buffers that grow on demand, 32-bit offsets, soft limit 256 MiB each (`CODESIZE_MAX`/`DATASIZE_MAX`). Instructions have a **wide** form (flag W = 0x10 in the instruction byte: 32-bit parameter field): code addresses (`PHPA.C`, `BRIA`, `BRIR`, `RSTR` with a target) are always wide because they are patched later (`cgen_patch_param()`), data offsets, `LINE` numbers and `PHIM` immediates only when they don't fit 16 (17) bits; the VM return stack, label/function code offsets (`lbloffs`/`codeoffs`), `CODEOFFS_NONE`/`DATAOFFS_NONE` (0xFFFFFFFF) and the DATA records (`type.8 next.32 payload`) are 32 bit. Identical read-only constants are shared (`cgen_data_const()`); integer literals in the int32 range are `PHIM` immediates (`cgen_push_number()`). The old limit (~600–1500 dense lines) is gone: 20000-line generated programs (up to 2.3 MB of code) compile and run; the code is ~3 % bigger than with 16-bit-only addresses. Still 16 bit: variable numbers, array dimensions, string length.
- **Compiler** (`bascomp`): recursive descent → heap syntax tree (`node_t`, growable branch arrays, `NODE_NONE`); all nodes freed by `cleanup_compiler()`. Names via `comp_node_name()` (no length limit).
- **Variables** (`vars`): heap `var_t` per variable, found by 16-bit variable number (table) or by type+name (hash). No fixed areas or compaction; ≤ 65535 variables; arrays row-major, ≤ `MAXELEMS` elements, one dimension ≤ 65535, ≤ 6 dimensions; function variables hold params + code offset.
- **Code generator**: `codegen.c` (expressions, LET, PRINT, SAVE, substring assignment, ERASE, program/line driver), `cgenctl.c` (GOTO/GOSUB/RETURN/LABEL, IF/UNLESS, FOR/NEXT, REPEAT/UNTIL, WHILE/WEND, UNTIL/UEND, AGAIN, END, POP, ON; line table + fixups; compile-time loop stack), `cgendecl.c` (DIM, DEF FN single- and multi-line, `FN A = expr`).
- **VM** (`vm.[ch]`, minimal executor): all instructions except `WRLV` and `BRK`; system functions (TI, INKEY$, FRE, ASC, LEN, VAL, STR$, BIN$/QUA$/OCT$/HEX$/DEC$, LEFT$/RIGHT$/MID$), SHEX (popen), SAVE (host callback `vm->save`), function calls with saved parameter contexts. Policies the ISA leaves open are documented in the comment at the top of `vm.h`.
- **Every statement in `bascomp.ebnf` has code generation.** The removed `basintp` interpreter stub is gone (the system compiles, it doesn't interpret).

- **ANSI colors on the text screen**: `ansi.[ch]` decodes `ESC [ … m` (SGR colors only: 0, 30-37/40-47, 90-97/100-107, 38;5;n / 48;5;n, 39, 49; everything else skipped) and calls back with text runs + palette colors; `sdlscr_ansi_puts()` / `sdlscr_ansi_printf()` (`sdlscreen.c`) feed them to `sdlscr_printf()`. No mutex on the text screen, by decision. `host_print` in `engine1999.c` uses `sdlscr_ansi_puts`, so BASIC `PRINT CHR$(27);"[31m"` sets colors; they persist until `ESC [ 0 m` (error messages and `Ready.` use plain output). Verified on the real screen (`engine1999`, `sdltest2`). The standard colors map to palette entries (`ansipal` in `ansi.c`; the palette is sorted by RGB value, not ANSI order). `38;5;n` / `48;5;n` index the engine's own 256-color palette, not xterm's: intended, users know the engine has its own palette (no xterm mapping wanted).
- **Syntax highlighting of LIST** (optional, callback-based): `detokenize_line_hl()` (`bastok.[ch]`, classes `hlclass_t` / `HL_*`) inserts the strings a `hlstyle_t` callback returns when the class of the text changes; `list_program_hl()` (`baspgm.c`); `repl_t.hlstyle` (used only when LIST writes to channel 0); `engine1999.c` sets `host_hlstyle()` with an ANSI SGR table (statements navy, control flow purple, commands red, functions teal, numbers maroon, strings green, shell literals magenta, comments silver, line numbers olive; operators, identifiers, punctuation default). Plain `detokenize_line()` is used by everything that parses the text again (SAVE ASCII, RENUM, label search). `repltest1` has 8 highlight cases (marker strings instead of escapes); 121 cases now. Checked on the real screen.
- **`EDIT n` / `EDIT label`** (language statement, `NT_EDITSTMT 0x63`, instruction `EDIT 0x140`, `VMREQ_EDIT`): a simple one-line editor. The REPL (`repl_edit_line()` in `basrepl.c`) detokenizes the line and calls the host callback `repl_t.edit( repl, text )`, which returns the edited text (malloc'ed) or 0 for ESC / cancel; the text goes to `repl_t.pending` and is entered like a typed line (`repl_enter_pending()`, a loop). `engine1999.c`: `host_edit()` uses `sdlscr_lineedit()` (`sdlscreen.c`: insert, LEFT/RIGHT/HOME/END, BACKSPACE/DELETE, RETURN accepts, ESC cancels; temporarily switches the break-on-ESC handling off). `EDIT` without a target opens the full-screen editor (next entry). Inside a program EDIT ends the run (like NEW). Tests: `repltest1` 14 EDIT cases (135 total), `vmtest1` 5 (385 total). The drawing/scroll arithmetic was checked in a scratch program; the editor was checked on the real screen by the user. "Ready." is still printed after an `EDIT` line (the edited line itself can't suppress it).
- **Line length**: a line at the prompt is limited to 4095 characters in both hosts (raised from 255 on 2026-11-01 by the owner: `PROMPT_BUFSIZE` / `CON_PROMPTMAX`; the screen holds fewer: 1919 on the window's 80 x 25, columns x (rows - 1) on a terminal; a redirected input takes all 4095). `EDIT` can edit longer lines (up to what fits the screen, buffer 2048), and enters the result without that limit.
- **Debug output is optional** (`basdebug.[ch]`, flag word `basdbg_flags`, all off by default, to stdout): `engine1999 --debug-tokenize | --debug-detokenize | --debug-parse | --debug-tree | --debug-code | --debug-all`, `--help`. The old unconditional `*** TOKEN` / disassembly printing in `bascomp.c` / `codegen.c` is now gated by the flags; `vmtest1 -v` = parse+code, `repltest1 -v` = all, `basictest2` sets parse. The fd-redirect silencing in `vmtest1`/`repltest1` was removed.
- **Host wiring is done**: `engine1999` runs the REPL in the main thread (`basrepl.[ch]`; the SDL screen thread only renders and queues keys). Callbacks: print → `sdlscr_puts`, INPUT → `sdlscr_lineinput`, GET → `sdlscr_getkey`, INKEY$ → `sdlscr_pollkey`, interrupt → `sdlscr_breakrequested`, SAVE → `repl_save_program`. **ESC = break** (while a line runs). Verified on the real screen under `Xvfb` + `metacity` + XTest key injection (PRINT, INPUT with prompt, GET, INKEY$, RUN/LIST, Break in a loop and at INPUT/GET, errors); the scripts are in the session scratchpad only, not in the repo. Details: `docs/compiler-and-vm.md` ("Host wiring").
- **`LOAD name$`, `RUN [line|label]`, `LIST [a][-[b]]`, `NEW`, `CLEAR`, `DELETE a[-[b]]`, `RENUM [a][-[b]][,step]` are language statements** (usable in programs; `cgenprog.c`, nodes 0x5C..0x62, instructions `LOAD 0x139`, `RUNP 0x13A`, `LIST 0x13B`, `NEW 0x13C`, `CLR 0x13D`, `DELE 0x13E`, `RENM 0x13F`; semantics in `docs/basic-language.md`). `LOAD`/`RUN`/`NEW` can't be executed by the VM: it stores a request (`vm->request`) and ends the run, and `repl_finish()` in `basrepl.c` carries it out iteratively (replace/recompile/restart). `LIST` is the callback `vm->list`. `NEW` deletes program + variables + functions and ends the run (back to the host/READY); `CLEAR` empties variables inside the VM (`vmem_clear_vars`: numbers 0, strings "", arrays emptied but still dimensioned; labels, functions and hidden `@` variables stay; the program and the DATA pointer are untouched). `DELETE` needs at least one end (like `LIST`, else use `NEW`). `RENUM`: the range selects the lines, the new numbers start at the first line of the range (10 without a start), step default 10; a single target means "to the end"; line references (GOTO, GOSUB, ON, THEN, ELSE, RESTORE, RUN, LIST, DELETE) are adjusted via the listing text; nothing changes if the numbers would overlap other lines or exceed 999999. Both end a running program (the code no longer matches). There are no host level commands left in `repl_enter()`. **`LOAD` typed in direct mode only loads (clears variables, doesn't run); inside a program it still runs the loaded program.** `engine1999` prints no "Ready." after entering or deleting a numbered program line (`handle_input()`). `LOAD` accepts binary `SAVE` files (magic header) and text listings.

- **Font**: all printable ASCII glyphs (0x21–0x7E) of `8x12font1.txt` were redrawn (original design, 2px stems, caps/digits rows 2–9, x-height rows 4–9, descenders rows 10–11); glyphs from 0x7F up unchanged (0x7F is the only non-empty one). ## Design decisions I took (revisit if unwanted)
- FOR/NEXT, REPEAT/UNTIL, WHILE/WEND, UNTIL/UEND are matched at compile time with a loop stack; FOR/WHILE/UNTIL test before the first pass. **An `UNTIL` closes the innermost loop if that is a REPEAT, otherwise opens an UNTIL..UEND loop** (so an UNTIL loop can't be opened directly inside a REPEAT body). `AGAIN [n]` restarts the body of the n-th innermost loop without re-testing/stepping. `ON` truncates the fraction and falls through when out of range. `END` inside a function ends the whole program.
- ERASE resets the array (arrays exist from parse time; no re-dimensioning). Multi-line DEF FN returns what was last assigned with `FN A = expr` (hidden variable `@FN<name>`; default 0 / empty string).
- Functions must be defined before they are called in the text, can't call themselves, and need a space: `DEF FN A(X)=…`, `FN A(…)` (the tokenizer reads `FNA` as one identifier). Array parameters aren't supported.
- DATA items are numeric literals (signed) and string literals only; they live in the data segment; `RESTORE n` means the first item in line ≥ n; a program run (`vm_run`) starts at the first item, `vm_run_at` keeps the pointer (so a persistent REPL VM keeps its data pointer across lines).
- The syntax tree stores the variable number (not a `var_t*`) in node data bytes.

- ESC is the break key while a line runs (not delivered as a key code); Break ends the program with `? Break in line N`. Output on channels other than 0 is discarded by `engine1999` (no devices yet). A direct mode line is compiled into the end of the code segment, run, and then discarded again (`cgen_rollback()` in `repl_execute()`) unless it defined a function, a label or DATA (`cgen_note_persistent()`); redefining a function leaves its old code behind until NEW/RUN.
- INPUT: prompt must be plain string literal(s); `;` adds "? ", `,` doesn't. Bad/missing field → "?Redo from start" (fields already stored stay stored), extra fields → "?Extra ignored", empty numeric field = 0. GET waits for a key (numeric variable gets the key code). INPUT/GET without `#ch` emit `PCHN 0`.
- `PRINT`, `INPUT` and `GET` all select their channel explicitly (`PCHN`, 0 when there is no `#ch`), because the VM's channel is sticky (`cgen_gen_channel0()` in `codegen.c`). Previously a plain `PRINT` after `PRINT #1,…` stayed on channel 1; fixed.
