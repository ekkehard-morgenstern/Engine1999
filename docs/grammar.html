The language at a glance

A quick reference of the syntax of the built-in BASIC, generated from bascomp.ebnf by perl grammar.pl (make grammar). Click a rule name to jump to its definition.

  • KEYWORD in capitals: a reserved word. Capitals that are not reserved words (OUTPUT, AS, EACH, LAYER ...) are recognized in that place only.
  • rule-name: another rule. ",": punctuation, quoted. <name$>: a kind of token (identifier, number, string ...).
  • [ x ] optional, { x } repeated, ( a | b ) a choice.

Lists, variables and literals

num-ex-list := num-expr { "," num-expr } .
str-ex-list := str-expr { "," str-expr } .
expr-list   := expr { "," expr } .
array-index := num-ex-list | str-expr .
array-sub := "(" array-index ")" .
array-dim-decl := num-ex-list | DYNAMIC | ASSOC .  (* (DYNAMIC and ASSOC are parsed but not supported: "Feature not supported yet") *)
array-decl := any-base-var-ref "(" array-dim-decl ")" .
array-decl-list := array-decl { "," array-decl } .
empty-array-ref := any-base-var-ref "(" ")" .
empty-array-ref-list := empty-array-ref { "," empty-array-ref } .
num-base-var-ref := <name> | <name%> .
num-var-ref      := num-base-var-ref [ array-sub ] .
str-base-var-ref := <name$> .
str-var-ref      := str-base-var-ref [ array-sub ] .
any-base-var-ref := <name> | <name%> | <name$> .

"identifier" in a rule stands for any identifier token (the word recognized there is written in capitals).

identifier := <ident> | <name> | <name%> | <name$> .
dec-lit := <number> | "0" .. "9" .
num-lit := dec-lit | <&Hhex> | <&Ooctal> | <&Qquaternary> | <&Bbinary> .
str-lit := <string> | <shell> | <brk-string> | <brc-string> .
str-lits := str-lit { str-lit } .

User-defined functions (DEF FN)

num-usr-fn-name := FN ( <name> | <name%> ) .
str-usr-fn-name := FN <name$> .
usr-fn-arg := any-base-var-ref [ "(" ")" ] .
usr-fn-arg-list := usr-fn-arg { "," usr-fn-arg } .
any-usr-fn-name := num-usr-fn-name | str-usr-fn-name .
singleline-usr-fn-body := "=" expr .

The value of a multi-line function is what the function name was last assigned (fn-assign-stmt) before
the end of the body; the statement is only valid inside the body of that function.
(RETURN expr, EXIT FN and LOCAL work in the body, too.)

multiline-usr-fn-body := <end-of-line> stmt-lines END FN .
usr-fn-body := singleline-usr-fn-body | multiline-usr-fn-body .
usr-fn-decl := any-usr-fn-name [ "(" [ usr-fn-arg-list ] ")" ] usr-fn-body .

An array parameter (declared with empty parentheses, usr-fn-arg) gets an array: A() (found by a lookahead for "name ( )", which is
no expression); the code generator checks that array parameters get arrays of their type and the others no array.

call-arg := empty-array-ref | expr .
call-args := call-arg { "," call-arg } .
num-usr-fn-call := num-usr-fn-name [ "(" [ call-args ] ")" ] .
str-usr-fn-call := str-usr-fn-name [ "(" [ call-args ] ")" ] .

Built-in functions

INT FIX ABS SGN SQR SIN COS TAN ATN EXP LOG FLOOR CEIL LOG2 LOG10: the usual meaning (FLOOR is INT; angles in the unit of DEG/RAD/GRAD, radians
by default). RND is RND(1) without an argument. PEEK(addr [, size]) reads the RAM (size 1 by default: see poke-stmt).
CVI CVL CVS CVD unpack a number from a binary string (big endian).

sys-num-fn-1-arg-call := ( ASC | VAL | LEN | CVI | CVL | CVS | CVD ) "(" str-expr ")" |
                           ( FRE | PLAYING | REMAIN | EOF | LOF | LOC |
                             INT | FIX | ABS | SGN | SQR | SIN | COS | TAN | ATN | EXP | LOG |
                             FLOOR | CEIL | LOG2 | LOG10 ) "(" num-expr ")" |
                           RND [ "(" num-expr ")" ] |
                           PEEK "(" num-expr [ "," num-expr ] ")" .
sys-str-fn-2-arg-call := ( BIN | QUA | OCT | DEC | HEX ) "$" "(" num-expr
                              [ "," num-expr ] ")" |
                         ( STR | CHR | MKI | MKL | MKS | MKD ) "$" "(" num-expr ")" |
    (* PEEK$(addr, length) is read like BIN$ (the length is mandatory: "Illegal argument" without it) *)
                         PEEK "$" "(" num-expr [ "," num-expr ] ")" |
                         ( LEFT | RIGHT ) "$" "(" str-expr "," num-expr ")" |
                         MID "$" "(" str-expr "," num-expr [ "," num-expr ] ")" |
                         INPUT "$" "(" num-expr [ "," chan-spec ] ")" .
sys-num-fn-arg-call := sys-num-fn-1-arg-call .
sys-str-fn-arg-call := sys-str-fn-2-arg-call .
sys-noarg-num-name := TI | ERL | PI .

MKI$ MKL$ MKS$ MKD$ pack a number into a binary string (2, 4, 4, 8 bytes, big endian), CVI CVL CVS CVD unpack it again
(the grammar is that of STR$/CHR$ resp. ASC/VAL/LEN, see sys-str-fn-2-arg-call and sys-num-fn-1-arg-call).

sys-noarg-num := sys-noarg-num-name .
sys-noarg-num-call := sys-noarg-num .

TIME$ "HH:MM:SS", DATE$ "YYYY-MM-DD", DATETIME$ both: the local time.

sys-noarg-str-name := INKEY | ADDRESS | ERR | TIME | DATE | DATETIME .
sys-noarg-str := sys-noarg-str-name "$" .
sys-noarg-str-call := sys-noarg-str .

The graphics functions (docs/graphics-subsystem.md) are a table in gfxops.c: RGB(r,g,b[,a]), POINT(x,y), TILE(x,y), and the named values
GFX("FRAME"), GFX("LAYER",n), GFX("PRIORITY",n), GFX("PALETTE",n,i), GFX("TARGET"), TXT("X"), TXT("Y"), TXT("FG"), TXT("BG"),
TXT("CHAR",x,y), TXT("FGAT",x,y), TXT("BGAT",x,y), TXT("WIDTH"), TXT("HEIGHT"), SPRITE("X"|"Y"|"IMAGE"|"ON"|"HITS"|"COLLIDE"|"MOVING",n):
the name is a string literal and the number of arguments after it depends on the name.

gfx-query-call := ( RGB | POINT | TILE ) "(" num-expr { "," num-expr } ")" |
                  ( GFX | TXT | SPRITE ) "(" <string> { "," num-expr } ")" .
num-func-call := num-usr-fn-call | sys-num-fn-arg-call | sys-noarg-num-call | gfx-query-call .
str-func-call := str-usr-fn-call | sys-str-fn-arg-call | sys-noarg-str-call .

Expressions

str-base-expr := str-var-ref | str-lits | str-func-call .
str-add-expr := str-base-expr { "+" str-base-expr } .
str-expr := str-add-expr .
num-sub-expr := "(" num-expr ")" .
num-base-expr := num-var-ref | num-lit | num-func-call | num-sub-expr .
num-unary-op := "-" | "+" | NOT .
num-unary-ex := [ num-unary-op ] num-base-expr .

\ (TOK_BACKSL) is the integer division, MOD the remainder: both truncate their operands.

num-mult-op  := "*" | "/" | "^" | "\\" | MOD .
num-mult-ex  := num-unary-ex { num-mult-op num-unary-ex } .
num-add-op   := "+" | "-" .
num-add-ex   := num-mult-ex { num-add-op num-mult-ex } .

SHL and ASL are LSHIFT, ASR is RSHIFT (arithmetic: keeps the sign), SHR shifts right with zero fill.

num-shift-op := LSHIFT | RSHIFT | SHL | SHR | ASL | ASR .
num-shift-ex := num-add-ex [ num-shift-op num-add-ex ] .
num-cmp-op   := "=" | "<>" | "<=" | ">=" | "<" | ">" .
num-cmp-ex   := num-shift-ex [ num-cmp-op num-shift-ex ] |
                str-expr num-cmp-op str-expr .
num-and-op   := AND | NAND .
num-and-ex   := num-cmp-ex { num-and-op num-cmp-ex } .

EQV is XNOR, NEQV is XOR, a IMP b is (NOT a) OR b, a NIMP b is a AND (NOT b). All of them are on this one level, left to right
(AsmBASIC puts IMP and EQV on a lower level of their own: use parentheses).

num-or-op    := OR | XOR | NOR | XNOR | EQV | NEQV | IMP | NIMP .
num-or-ex    := num-and-ex { num-or-op num-and-ex } .
num-expr     := num-or-ex .
expr         := num-expr | str-expr .

Input and output

save-stmt := SAVE str-expr [ "," <name> ] .
chan-spec := "#" num-expr .
print-sep := "," | ";" .
print-arg := expr [ print-sep ] .
print-arg-list := print-arg { print-arg } .
print-stmt := ( PRINT | WRITE ) [ chan-spec [ "," ] ] [ print-arg-list ] .
data-item := [ "+" | "-" ] num-lit | <string> .
data-stmt := DATA data-item { "," data-item } .
read-stmt := READ ( num-var-ref | str-var-ref ) { "," ( num-var-ref | str-var-ref ) } .
restore-stmt := RESTORE [ goto-target ] .

INPUT: the prompt is shown followed by "? " if it is followed by a semicolon (or if there is no prompt); a comma
after the prompt suppresses the "? ". GET reads one key per variable (a string variable gets the character, a
numeric variable its code).

input-var := num-var-ref | str-var-ref .
input-stmt := [ LINE ] INPUT [ chan-spec "," ] [ str-lits ( ";" | "," ) ] input-var { "," input-var } .
get-stmt := GET [ chan-spec "," ] input-var { "," input-var } .
io-stmt := save-stmt | print-stmt | input-stmt | get-stmt | data-stmt | read-stmt | restore-stmt |
           open-stmt | close-stmt | address-stmt | record-stmt | fileop-stmt .

Assignment and declarations

num-assign := num-var-ref "=" num-expr .
str-assign := str-var-ref "=" str-expr .
substr-op := LEFT | MID | RIGHT .
substr-assign := substr-op "$" "(" expr-list ")" "=" str-expr .
any-assign := num-assign | substr-assign | str-assign .
assign-list := any-assign { "," any-assign } .
let-stmt := [ LET ] assign-list .
dim-stmt := DIM array-decl-list .
erase-stmt := ERASE empty-array-ref-list .
def-stmt := DEF usr-fn-decl .
fn-assign-stmt := any-usr-fn-name "=" expr .
assign-stmt := let-stmt | dim-stmt | erase-stmt | def-stmt | fn-assign-stmt .

Control flow, procedures

for-stmt := FOR num-base-var-ref "=" num-expr ( TO | DOWNTO ) num-expr [ STEP num-expr ] | for-each-stmt .

FOR EACH [ key, ] value IN array() loops over all elements of an array (flat row-major order; key = the flat index).
EACH, IN and DOWNTO are identifiers that are recognized in this place, not keywords. DOWNTO counts down by the STEP value (default 1).

for-each-stmt := FOR EACH any-base-var-ref [ "," any-base-var-ref ] IN empty-array-ref .
next-stmt := NEXT [ num-base-var-ref { "," num-base-var-ref } ] .
goto-kw := GOTO | GOSUB | GO ( TO | SUB ) .
goto-target := dec-lit | <name> .
goto-stmt := goto-kw goto-target .

RETURN expr (a number or string according to the function) is only valid in the body of a FUNC or a multi-line DEF FN: it sets the
result and leaves. Without a value it is the RETURN of GOSUB.

return-stmt := RETURN [ expr ] .
label-stmt := LABEL <name> .
endif-kw := END IF | ENDIF .
endunless-kw := END UNLESS | ENDUNLESS .
then-kw := THEN [ goto-kw ] .

IF c THEN GOSUB 100 : PRINT "x" [ ELSE ... ]: a colon after the jump target continues the THEN branch, which then is a statement
list (GOSUB 100 : PRINT "x"); the rest of the line is not run when the condition is false.

singleline-if-stmt := ( IF | UNLESS ) num-expr
           ( then-kw  goto-target [ ELSE goto-target ] |
             then-kw  goto-target ":" stmt-list [ ELSE stmt-list ] |
             THEN stmt-list   [ ELSE stmt-list   ] ) .
multiline-if-stmt := IF num-expr THEN <end-of-line>
                        stmt-lines
                        [ ELSE stmt-lines ]
                        endif-kw |
                     UNLESS num-expr THEN <end-of-line>
                        stmt-lines
                        [ ELSE stmt-lines ]
                        endunless-kw <end-of-line> .
end-stmt := END .  (* not followed by IF, UNLESS, FN, PROC or FUNC *)
pop-stmt := POP .
again-stmt := AGAIN [ dec-lit ] .

EXIT / LEAVE / ITERATE [n] work on the n-th innermost loop (resolved by the code generator, like AGAIN); EXIT PROC / FUNC / FN leaves the
procedure or function being defined.

exit-stmt := ( EXIT | LEAVE ) ( PROC | FUNC | FN ) | ( EXIT | LEAVE | ITERATE ) [ dec-lit ] .
repeat-stmt := REPEAT .
until-stmt := UNTIL num-expr .
while-stmt := WHILE num-expr .
wend-stmt := WEND .
uend-stmt := UEND .
on-stmt := ON num-expr goto-kw goto-target { "," goto-target } .

Loops are matched by the code generator, like FOR and NEXT: WHILE .. WEND, UNTIL .. UEND, REPEAT .. UNTIL.
An UNTIL closes the innermost open loop if that is a REPEAT; otherwise it opens an UNTIL .. UEND loop.

Procedures and functions. The header stands alone on its line, the body is jumped over where it stands. A FUNC is called like a
user function (FN name(args)) and has to be defined before the line that calls it; a PROC is called with CALL (checked by the code
generator, so the PROC may follow). Parameters are variables passed by value (array parameters, written with empty parentheses, by
reference). LOCAL makes variables local to the call: scalars, LOCAL T(10) (a new array, like DIM) or LOCAL D() (a local zeroed copy
of the array D). It is only valid in the body (code generator). The result of a FUNC is what "FN name = expr" or RETURN expr set.
An empty body is allowed (END PROC / END FUNC right after the header).

proc-stmt := PROC <name> [ "(" [ usr-fn-arg-list ] ")" ] <end-of-line> [ stmt-lines ] END PROC .
func-stmt := FUNC any-base-var-ref [ "(" [ usr-fn-arg-list ] ")" ] <end-of-line> [ stmt-lines ] END FUNC .
call-stmt := CALL <name> [ "(" [ call-args ] ")" ] .
local-item := empty-array-ref | array-decl | any-base-var-ref .
local-stmt := LOCAL local-item { "," local-item } .

RESUME (in an ON ERROR handler) runs the statement that failed again, RESUME NEXT continues behind it, RESUME target jumps there. The
statement is the innermost one (inside IF .. THEN: the statement of the branch). Not possible after an error inside a PROC / FUNC call.

resume-stmt := RESUME [ NEXT | goto-target ] .
control-flow-stmt := for-stmt | next-stmt | goto-stmt | return-stmt | label-stmt | end-stmt | pop-stmt | again-stmt | exit-stmt |
                     repeat-stmt | until-stmt | while-stmt | wend-stmt | uend-stmt | on-stmt |
                     proc-stmt | func-stmt | call-stmt | local-stmt | resume-stmt | stop-stmt |
                     singleline-if-stmt | multiline-if-stmt .

Debugging and memory: STOP, CONT, TRACE, AUTO, POKE

STOP ends the run like Break but keeps its state for CONT; TRACE ON prints [line] for every program line; AUTO prompts for line numbers
(the host does that: engine1999.c); start and step default to 10.

stop-stmt := STOP .
cont-stmt := CONT .
trace-stmt := TRACE ( ON | OFF ) .
auto-stmt := AUTO [ num-expr [ "," num-expr ] ] .

POKE writes the RAM (1 MiB, big endian): size 1 (default), 2, 4 integers, -4 single, -8 double; a string value writes its bytes.

poke-stmt := POKE num-expr "," expr [ "," num-expr ] .

Program commands

Program commands. They work inside programs, too. RUN and LOAD restart the program (RUN: after clearing all
variables, at the given line or label; LOAD: replace the program by the one in the file and run it from the
beginning); LIST lists the program: a single target lists that line, "a-b" the range, "a-" to the end, "-b" from the start.

load-stmt := LOAD str-expr .
run-stmt := RUN [ goto-target ] .
list-stmt := LIST [ goto-target ] [ "-" [ goto-target ] ] .

NEW deletes the program and all variables and returns to the host (READY prompt): the running program ends.
CLEAR empties the variables (numbers 0, strings "", arrays emptied but kept dimensioned) and the program goes on;
labels and functions are not variables in this sense and stay.

new-stmt := NEW .
clear-stmt := CLEAR .

DELETE removes the lines of a range (same syntax as LIST, but at least one end is required: use NEW to delete all).
RENUM [a][-b][,step] renumbers the lines in the range (all lines without a range): the new numbers start at the first
line of the range (a; 10 without a start) and advance by step (10 if omitted); a start alone means "from a to the end".
References to renumbered lines (GOTO, GOSUB, ON, THEN, ELSE, RESTORE, RUN, LIST, DELETE) are adjusted, labels are not
affected. Both change the stored program, so the running program ends (its code no longer matches the program).

delete-stmt := DELETE ( goto-target [ "-" [ goto-target ] ] | "-" goto-target ) .
renum-stmt := RENUM [ goto-target ] [ "-" [ goto-target ] ] [ "," num-expr ] .

EDIT n / EDIT label: a simple line editor for that line (see docs/basic-language.md); the edited line is then entered
like a typed one. It ends the running program (like NEW). EDIT alone opens the full-screen editor (docs/display-engine.md).

edit-stmt := EDIT [ goto-target ] .

MONITOR opens the machine monitor (text screen 2). It ends the running program (like NEW).

monitor-stmt := MONITOR .

MERGE name enters the lines of a program file into the stored program: a line with the number of a stored line replaces it,
the others are inserted. Variables stay; the stored program changes, so the running program ends (like RENUM). With APPEND
(an identifier, not a keyword) the file's lines are numbered in steps of 10 behind the last stored line (the first free
multiple of 10; 10 for an empty program) and the line numbers they refer to are adjusted; the stored program is not
renumbered. A label that both programs define (in lines that are not replaced) is an error and nothing changes.
CHAIN name replaces the program by the file and runs it, like LOAD followed by RUN, but the variables of the old program that
the new one also uses keep their values (same name and type; arrays only with the same dimensions). CHAIN MERGE name merges
the file into the stored program (as MERGE) and runs the result. The optional target is where the run starts (default:
the first line). Functions, labels and DATA are those of the new program; SFX definitions are kept.

merge-stmt := MERGE str-expr [ "," APPEND ] .
chain-stmt := CHAIN [ MERGE ] str-expr [ "," goto-target ] .

FILES [spec] lists files like "ls -ltr" (oldest first) without mode bits and owners: size, time, name with the "ls -F"
indicator. No spec = the current directory (hidden names left out); a directory lists its entries; a pattern with * ? [ ]
lists the matches. The screen listing is colored and stops after each page (any key goes on, Q or ESC stops).

files-stmt := FILES [ str-expr ] .

Sound

Sound (see docs/sound.md). Channels are 1..8. SOUND ch, freq, beats [, vol]: a tone of freq Hz (20..20000; 0 = a rest) for
"beats" (the channel's next event follows after that; 0 = until the next SOUND), vol 0..1 (default 0.5). SOUND OFF silences
one channel / all of them at once, SOUND SYNC lines up the time of the channels (to start them together). PLAY plays one
music string per voice (voice n = channel n, all start together); both return at once, PLAYING(ch) is -1 while the channel
still sounds or has music queued, else 0. WAVE ch, w: 0 sine, 1 square, 2 triangle, 3 noise. TEMPO bpm: beats per minute.

sound-stmt := SOUND num-expr "," num-expr "," num-expr [ "," num-expr [ "," num-expr ] ] |
              SOUND OFF [ num-expr ] | SOUND SYNC num-expr { "," num-expr } |
              PLAY str-expr { "," str-expr } | WAVE num-expr "," num-expr | TEMPO num-expr |
              ( PITCH | VOLUME ) num-expr "," num-expr |
              ENVELOPE num-expr [ "," num-expr "," num-expr "," num-expr "," num-expr ] |
              ( VIBRATO | TREMOLO ) num-expr "," num-expr "," num-expr |
              SFX num-expr "," str-expr | SFX num-expr [ "," num-expr ] .

Sound effects (docs/sound.md): SOUND ch, f1, beats, vol, f2 glides from f1 to f2 during the tone; PITCH ch, f and VOLUME ch, v
change a sounding channel at once; ENVELOPE ch, attack, decay, sustain, release shapes the tones (ENVELOPE ch alone: back to the
default); VIBRATO / TREMOLO ch, rate, depth; SFX n, a$ stores a music string as effect n (1..64), SFX n [, ch] plays it
(no channel: a free one, the highest first).

Timing: WAIT, AFTER, EVERY

WAIT n sleeps for n/60 seconds (the unit of TI) without using the processor; ESC breaks it. WAIT 0 returns at once.

wait-stmt := WAIT num-expr .

AFTER delay [, timer] GOSUB|GOTO target runs the handler once after "delay" ticks (1/60 s, the unit of TI and WAIT), EVERY
delay [, timer] GOSUB|GOTO target runs it again and again at that interval. Four timers 0..3 (default 0); a timer holds one
AFTER or EVERY, setting it again replaces it. A handler entered by GOSUB returns to where the program was interrupted with
RETURN; while it runs, only a timer with a higher number may interrupt it. A handler is entered between two statements
(also during WAIT), not during INPUT or GET. AFTER OFF [timer] / EVERY OFF [timer] clear all timers (or that timer) of
that kind. Timers end with the run.

timer-stmt := ( AFTER | EVERY ) ( OFF [ num-expr ] | num-expr [ "," num-expr ] goto-kw goto-target ) .

Files and devices

Files and devices (docs/io-subsystem.md). A file name may start with "driver:" (file, null, mem); names without a prefix belong to
the ADDRESS driver. OPEN name FOR INPUT|OUTPUT|APPEND AS #n, or OPEN "I"|"O"|"A", #n, name; CLOSE closes the channels given (all
of them without any). OUTPUT, APPEND and AS are identifiers recognized in context. ADDRESS name (a bare identifier or a string
expression) chooses the default driver, ADDRESS alone swaps with the previous one; RUN resets it. WRITE is PRINT with quoted
strings and commas between the items. LINE INPUT reads a whole line into one string variable.

open-stmt := OPEN str-expr ( FOR ( INPUT | OUTPUT | APPEND ) AS chan-spec | "," chan-spec "," str-expr ) .
close-stmt := CLOSE [ chan-spec { "," chan-spec } ] .
address-stmt := ADDRESS [ identifier | str-expr ] .

Random access: OPEN ... FOR RANDOM AS #n [LEN = reclen] (or OPEN "R", #n, name [, reclen]; FOR UPDATE / "U" = read and write
without records). FIELD binds string variables to slices of the record buffer, LSET / RSET fill a slice (padded with spaces),
GETREC / PUTREC read / write record rec (1.., none = the next one). AS is an identifier recognized in context.

record-stmt := FIELD chan-spec "," num-expr AS str-var-ref { "," num-expr AS str-var-ref }
             | ( LSET | RSET ) str-var-ref "=" str-expr
             | ( GETREC | PUTREC ) chan-spec [ "," num-expr ] .

KILL deletes a file, RENAME renames it (both names on the same driver), MKDIR makes and CHDIR enters a directory, SEEK #n, pos
moves the position of an open channel (bytes from the start).

fileop-stmt := ( KILL | MKDIR | CHDIR ) str-expr | RENAME str-expr TO str-expr | SEEK chan-spec "," num-expr .

Errors, random numbers, angles

ON ERROR GOTO / GOSUB sets a handler for run time errors, ON ERROR OFF clears it (ERROR is an identifier recognized after ON).
ERR$ is the text of the last error, ERL its line number.

on-error-stmt := ON ERROR ( goto-kw goto-target | OFF ) .

Numeric functions: INT FIX ABS SGN SQR SIN COS TAN ATN EXP LOG RND ( num-expr ) (RND alone is RND(1)); PI. \ (integer division) and MOD
are at the level of * and /. RANDOMIZE [ seed ] seeds RND.

randomize-stmt := RANDOMIZE [ num-expr ] .

DEG, RAD (the default) and GRAD choose the unit of the angles of SIN COS TAN ATN.

angle-stmt := DEG | RAD | GRAD .

Graphics, sprites and the text screen

Graphics, tiles, sprites, text screen areas (docs/graphics-subsystem.md). The statements are a table in gfxops.c, the parser, the code
generator and the VM read it: group word, name word, and the arguments from a signature. GFX, TXT, TILE, SPRITE, DESIGN, CLS, LOCATE, COLOR
are keywords; the second words (LAYER, PSET, ...) are identifiers recognized after the group word, so they stay free as variable names.
x, y, c ... are num-expr; a$ is a str-expr, a string variable where the statement returns a string (GRAB, TILE GET, SPRITE GET, TXT SAVE).

gfx-stmt := GFX ( LAYER num-expr "," ( ON | OFF ) | PRIORITY num-expr "," num-expr |
                      PALETTE num-expr "," num-expr "," num-expr | PALNAME num-expr "," num-expr "," str-expr |
                      PALRESET [ num-expr ] | BACKDROP num-expr | TARGET num-expr | PEN num-expr |
                      MODE ( SET | CLEAR | XOR | OR | AND ) | CLEAR [ num-expr ] | PSET num-expr "," num-expr [ "," num-expr ] |
                      LINE num-expr "," num-expr "," num-expr "," num-expr [ "," num-expr [ "," ( B | BF ) ] ] |
                      CIRCLE num-expr "," num-expr "," num-expr [ "," num-expr [ "," num-expr "," num-expr
                                                                                                    [ "," num-expr ] ] ] |
                      PAINT num-expr "," num-expr "," num-expr [ "," num-expr ] |
                      RADIUS num-expr "," num-expr "," num-expr "," num-expr [ "," num-expr ] |
                      GRAB num-expr "," num-expr "," num-expr "," num-expr "," str-var-ref |
                      BLIT str-expr "," num-expr "," num-expr [ "," TRANS ] |
                      TEXT num-expr "," num-expr "," str-expr [ "," num-expr [ "," num-expr [ "," num-expr ] ] ] |
                      DRAW str-expr | VSYNC | RESET [ ALL ] ) .
txt-stmt := TXT ( FILL num-expr "," num-expr "," num-expr "," num-expr [ "," num-expr [ "," num-expr
                                                                                                          [ "," num-expr ] ] ] |
                      COPY num-expr "," num-expr "," num-expr "," num-expr "," num-expr "," num-expr |
                      INVERT num-expr "," num-expr "," num-expr "," num-expr | SAVE str-var-ref | LOAD str-expr ) .
tile-stmt := TILE ( DEF num-expr "," str-expr | GET num-expr "," str-var-ref |
                        SET num-expr "," num-expr "," num-expr | FILL str-expr | SCROLL num-expr "," num-expr ) .

SPRITE n, x, y [, image] places a sprite; MOVETO makes the engine move it; the collision word list is OFF, or ON [, TILES].

sprite-stmt := SPRITE ( DEF num-expr "," str-expr | GET num-expr "," str-var-ref | SEQ num-expr "," str-expr |
                            num-expr "," ( ON | OFF | PRIORITY num-expr | IMAGE num-expr |
                                                 ANIM num-expr "," num-expr "," num-expr |
                                                 MOVETO num-expr "," num-expr "," num-expr |
                                                 COLLISION ( OFF | ON [ "," TILES ] ) |
                                                 num-expr "," num-expr [ "," num-expr ] ) ) .
cls-stmt := CLS .
locate-stmt := LOCATE num-expr "," num-expr .
color-stmt := COLOR num-expr [ "," num-expr ] .
symbol-stmt := SYMBOL num-expr "," str-expr .

DESIGN defines a sprite, tile or character by pictures: the following "@" statements (design-row) give one row each, executed in
order; the picture ends after the last row the size needs. base is the first palette index of the picture's characters.

design-stmt := DESIGN ( SPRITE | TILE | CHAR ) num-expr [ "," num-expr ] .
design-row := "@" str-expr .

ON COLLISION GOSUB / GOTO target runs the handler when sprites collide (polled between statements, highest priority of the timers); OFF clears it.

on-collision-stmt := ON COLLISION ( goto-kw goto-target | OFF ) .
gfx-all-stmt := gfx-stmt | txt-stmt | tile-stmt | sprite-stmt | cls-stmt | locate-stmt | color-stmt | symbol-stmt | design-stmt | design-row | on-collision-stmt .

Statements and lines

The statements by group: io-stmt (PRINT, INPUT, GET, DATA, READ, OPEN, CLOSE, ...), prog-stmt (program commands, sound, graphics, timers, error
handling, debugging; they work inside programs, too), assign-stmt (LET, DIM, ERASE, DEF FN) and control-flow-stmt (loops, IF, GOTO, PROC ...).
Several statements on a line are separated by a colon; a line may end with a comment (an apostrophe).

prog-stmt := gfx-all-stmt | load-stmt | run-stmt | merge-stmt | chain-stmt | files-stmt | timer-stmt | list-stmt | new-stmt | clear-stmt |
             delete-stmt | renum-stmt | edit-stmt | monitor-stmt | sound-stmt | wait-stmt | on-error-stmt | randomize-stmt | angle-stmt |
             cont-stmt | trace-stmt | auto-stmt | poke-stmt .
stmt := io-stmt | prog-stmt | assign-stmt | control-flow-stmt .
stmt-list := stmt { ":" stmt } .
stmt-line := [ stmt-list ] [ <'comment> ] <end-of-line> .
stmt-lines := stmt-line { stmt-line } .

Notes: what a grammar cannot say

  • Capital words that are not reserved words (OUTPUT, APPEND, AS, ERROR, COLLISION, EACH, IN, DOWNTO, LAYER, PSET, ...) are identifiers that are recognized in that place, not keywords; "identifier" stands for any identifier.
  • Several rules are decided by one or two tokens of lookahead (FOR EACH against FOR v = ..., "name ( )" as an array argument, THEN <name> as a label or as the start of an assignment, END followed by IF / UNLESS / FN / PROC / FUNC) and by trying alternatives in the order written (an alternative that fails after it consumed input is rewound).
  • What the code generator checks, not the parser: that NEXT, WEND, UEND and UNTIL match an open loop of their kind, that EXIT, ITERATE and AGAIN have a loop (and EXIT PROC / RETURN expr / LOCAL a procedure or function body), that FN name = expr is the function being defined, the types and number of call arguments of a PROC, that the target lines of GOTO / GOSUB / ON / RESUME exist, and that a DIM array is not declared twice.
  • Variables and arrays are looked up while the line is parsed (DIM first, then use; a FUNC before the line that calls it); a PROC may be called before its definition.
  • Line numbers belong to the stored program (a line "10 PRINT" is stmt-line with a number in front); direct mode lines are stmt-line without one, and a body with END PROC / END FUNC / END FN / multi-line IF needs numbered lines (the header ends with TOK_EOL).
  • Numbers (decimal, hex, octal, quaternary, binary), strings and shell literals are tokens made by the tokenizer, not described here: see docs/basic-language.md ("Tokenized line") for the characters. Case does not matter (the preprocessor upper-cases everything outside quotes).
  • Precedence is as the nesting above says (unary, * / \ ^ MOD, + -, shifts, comparisons, AND NAND, OR XOR NOR XNOR EQV NEQV IMP NIMP): ^ is on the level of *; a comparison or shift takes at most one operator; the logical operators work on 32 bit integers (true is -1).
